## At a glance

- **Role:** Product designer, assigned to the project. I helped decide which features were worth building, defined how each should work at its minimum, and built the design system under all of them.
- **Scope:** A white-label base for web and mobile: 13 reusable features and a design system with 1,000+ components.
- **Decision that mattered:** standardizing only the features most projects actually need, built to be reused as complete modules (designed, validated, coded and QA'd).
- **Outcome:** MVPs with basic features went from 2–3 months to under one. Atama is now the starting point for all five designers at the company, with 29 Figma projects built on it.

## The problem

### The same features, built again and again.

Every new product at the company needed the same basics: sign up, user management, surveys, tasks. Each time, we rebuilt them from scratch. That cost design time, development time and QA time, and it delayed the moment we could put something in front of real users.

For clients it was costly too. A lot of the budget went to rework on basic features, instead of the parts that made their product different.

## What we standardized

### Not everything. Only what most products need.

The first step was deciding what belonged in a reusable base. We reviewed every project we had built, the ones still in progress and what clients were asking for, and identified the features that kept coming back. For each, I researched what we'd done before and what the ideal version looked like, then defined the minimum it needed to work inside any product.

I was assigned the project, but I took part in every decision about which features to include, so the base reflected what we actually needed.

## The design system

### A foundation that other designers can start from, and change without breaking.

Before designing any feature, I built the system that would hold them all. It follows atomic design, in three layers:

1. **Foundations:** tokens for color, typography, spacing and more, for both web and mobile.
2. **Components:** buttons, inputs and the rest of the building blocks.
3. **Patterns:** headers, modals, tables, cards and other elements made of those components.

The result is more than 1,000 components (including variants), 108 styles and 452 variables.

Customizing it for a client doesn't mean redesigning anything. Color and typography tokens live in the foundations, so adjusting them updates the whole system. A new client's brand is one change, not hundreds.

## Outcomes

### MVPs in under a month, and a base the whole team now uses.

By the end of 2024 most of the features were ready to use in Figma, front end and back end. In the projects that started in 2025, the difference showed: MVPs with basic features that used to take 2–3 months came in under one. Because the basics were already solved, we could put a working product in front of real users earlier and spend our time on what each client actually needed.
